# Per-stage design choices (A2 deliverable). Fill every cell.
| Stage | Problem statement | Data | Model | Methods | Design | Development | Deployment | MLOps |
|---|---|---|---|---|---|---|---|---|
| 0 Frame | Build a grounded scanned-page QA agent for soil science and crop-rotation decisions from historical Bangla manuals. | 3 Internet Archive scanned books, 776 pages, non-English Bangla script with degraded scans and old orthography. | Stage 0 is model-agnostic; establishes constraints and acceptance targets for downstream model choices. | Commit to evidence-grounded answers with abstention on weak retrieval evidence; optimize reliability over recall. | Fixed pipeline contracts and stage ordering from starter repo; document-by-document split to prevent leakage. | Encode decisions in `configs/task.yaml`, provenance in `data/provenance.md`, and this per-stage table as A2 baseline. | Deployable target is API-served doc-agent with citations, but Stage 0 only sets the operational objective and constraints. | Reproducible seed/config driven runs; track target metric: answer reliability >= 0.90 under noisy OCR conditions. |
| 1 Ingest+Enhance | Convert 776 raw scanned PDFs into clean, deskewed page images that downstream stages can process reliably; skip blank/near-blank pages without discarding sparse-but-real content (chapter dividers, section headings). | Same 776-page, 3-book corpus from A1; inputs are PDFs; outputs are PNG images in `data/interim/pages/`. Blank pages filtered by a 3-signal check (ink ratio, min blob area ≥15, min blob count ≥3) derived from EDA §1 — a naive ink-density-only threshold over-flagged legitimate sparse pages. | No learned model at this stage; enhancement disabled (`enhance: {enabled: false}`). Blank-page filter is heuristic. | pdf2image at render_dpi=150 (matched to Tesseract's optimal input resolution per EDA §8 preprocessing sweep). Otsu binarisation + morphological filtering for blob detection. OpenCV-based skew estimation via HoughLinesP for deskew. | Enhancement set to disabled: tested VAE/diffusion-based denoising as a bonus path but deprioritised for A2 given our corpus is already at usable quality per EDA §4 scan-quality metrics (mean contrast_std and blur_score acceptable across all three books). Cache keyed by `(doc_id, page_stem)` — re-render only if pages are missing. | Parameters (`render_dpi`, `ink_ratio_threshold`, `min_blob_area`, `min_blob_count`) all live in `configs/task.yaml`; code reads only from there. EDA §1 histograms provided empirical grounding for threshold choices against `data/blank/` reference pages. | Runs offline, batch, CPU, once per corpus. Output PNGs are not committed to git; `scripts/get_data.sh` + this stage recreates them. | Blank-page stats logged per book; parameter sweep reproducible by re-running EDA §1 cell. |
| 2 Layout | Detect and classify typed regions (heading, text, table, figure) on each page image so that OCR runs on the right pieces and figures are skipped — preventing garbage tokens from entering the index. | Input: page PNGs from Stage 1. Output: `Region(page_id, bbox, kind)` objects. Corpus is 1930s–40s Bangla agricultural scans — not in any layout model's training distribution, so recall on degraded/unusual pages was the primary concern. | DocLayout-YOLO (juliozhao/DocLayout-YOLO-DocStructBench), pretrained, weights unmodified. Downloaded from HuggingFace Hub at runtime; no fine-tuning. | imgsz=1184, score_thr=0.085 (lowered from 0.25 to recover faint headings and captions). Class-agnostic NMS (dedup_iou_thr=0.5) to remove same-object duplicate detections at low threshold. Containment filter (containment_thr=0.85) to drop sub-boxes fully inside larger boxes. OCR-confidence coverage-net (`_classify_gap`) for remaining uncovered ink. Per-line Bangla-ratio gate (`whole_bangla_ratio_thr=0.85`) prevents dual-lang resolution on lines that are already clean Bangla. | Tried classical OpenCV heuristic first (row-ink periodicity): failed because Bangla's matra glyph-linking collapses dense paragraphs into single blobs, misclassifying text as figure. Tried Detectron2+PubLayNet: blocked by platform packaging issues (macOS Dropbox-config fragility, no native Windows support). DocLayout-YOLO was the first model that worked cross-platform without a build toolchain. Validated visually on 20 sampled pages before running full corpus. | Parameters in `configs/task.yaml` (`layout.score_thr`, `layout.imgsz`); dedup/containment thresholds in code constants with docstring justification. `visualize_regions()` writes debug PNGs to `data/debug_layout/` gated behind `cfg["layout"]["debug_visualize"]` flag. | Runs offline, batch, CPU or GPU (`device: cpu` default). Model weights cached by HuggingFace Hub after first download — no network needed for subsequent runs. | Layout detection iteration documented: classical → Detectron2 → DocLayout-YOLO. Visual validation on 20 pages is the acceptance criterion for this stage. |
| 3 OCR | Transcribe detected text/heading/table regions from Bangla scanned-page images into machine-readable text; skip figure regions entirely. Handle mixed Bangla+English content (species names, citations, source attributions) without degrading the Bangla majority. | Input: Region objects from Stage 2. Ground truth: Gemini-verified transcriptions in `data/ground-truth-ocr/`. Held-out test set: Krishi-Darpan (188 pages, never seen during threshold tuning). Corpus challenge: Bangla conjunct script + 90-year-old degraded scans + embedded English/Latin citations. | Tesseract (`lang=ben`, `oem=1` LSTM-only) as primary OCR engine. mT5-small fine-tuned corrector (`haha34/mt5-small-2200`, private Kaggle dataset) as post-OCR correction layer. Tesseract chosen over EasyOCR/PaddleOCR/Surya per EDA §7 bake-off (fill in winner + CER/WER numbers once §7 is run). | Line-level dual-lang resolution: run plain `ben` OCR first; only lines below Bangla-ratio threshold (`whole_bangla_ratio_thr=0.85`, computed over all significant characters not just alphabetic ones — a bug fix that revealed `25015 ০£ 20৩00`-type citation lines were invisible to alphabetic-only ratio) get per-word `ben`/`eng` recheck (`per_word_conf_thr=35.0`, `swap_margin=30.0`). mT5 correction gated by same Bangla-ratio: citation/garbled lines bypass corrector (which hallucinated `CaCO`/`Screw Officer` loops on out-of-distribution content). Repetition guard (`repetition_penalty=1.3`, `no_repeat_ngram_size=3`) + degenerate-output fallback to raw text. All results cached per `(doc_id, page_stem)` — re-OCR only on cache miss. | Corpus-wide (12-page debug sample): CER=0.0897, WER=0.1900 (corrected) vs CER=0.0986, WER=0.3003 (raw). Full 742-page corpus (earlier run): CER=0.1160, WER=0.2653 (corrected). Held-out Krishi-Darpan: CER=0.1070, WER=0.2947. Known limitation: citation lines mixing Bangla with English source attributions and Latin botanical terms remain a documented weak point; pipeline handles gracefully (falls back to raw rather than hallucinating) but doesn't solve perfectly. | All OCR parameters in `configs/task.yaml` (`ocr.tesseract_lang`, `ocr.use_corrector`, `ocr.corrector_batch_size`, thresholds). mT5 corrector downloaded from Kaggle via `kagglehub` using credentials from `.env`; cached locally after first pull. Region cache at `data/interim/ocr/` prevents re-running Tesseract on unchanged pages. | Offline, batch, CPU. mT5 inference on CPU at ~30 lines/sec (acceptable for one-time index build). Cache-everything design means full re-run only needed on corpus or model changes. | CER/WER tracked per run (corpus-wide + held-out split). Tesseract-raw vs mT5-corrected comparison computed at every run. `held_out_docs` config key enforces clean separation of test set throughout. |
| 4 Index | Convert OCR text chunks into a searchable dense vector index with accurate chunk-to-page provenance, so retrieval in Stage 5 can return both the relevant text and the source page citation. | Input: Chunk objects from `chunk.split()`. Chunks are region-aware (heading-anchored, table-isolated, sentence-boundary-safe with `।`-based splitting, token-counted against `BAAI/bge-m3` tokenizer to prevent truncation). Index covers 1,814 chunks from 749 non-blank pages. | BAAI/bge-m3 (SentenceTransformer, pretrained, unmodified) for embedding. FAISS IndexFlatIP for exact inner-product search. Config declares `type: faiss:flat`; brute-force exact search is appropriate at this corpus scale (~1800 chunks) and preferable for `robust-and-reliable` NFR over approximate HNSW. | Chunking: region-aware merging to `target_tokens=256`, hard cap `max_tokens=512`, `overlap_tokens=32`; tables isolated as standalone chunks; headings merged into the following text chunk not stored alone. Embedding: `normalize_embeddings=True` (BGE-M3 trained for cosine similarity on unit-normalized vectors); 1024-dim float32 dense vectors; `batch_size=16`. Index: IndexFlatIP (inner product on normalized vectors = cosine similarity); `vectors[i]` maps directly to `chunks[i]` via `chunks.jsonl` row order. Per-chunk caching: `store.build()` checks existing chunk IDs; only adds vectors for chunks missing from the index — full rebuild only when chunk IDs change. | Fixed-size token/character chunking discarded: ignores region boundaries, splits heading from body, blends table cells with prose. `paraphrase-multilingual-mpnet-base-v2` (768-dim) discarded in favour of BGE-M3 (1024-dim, broader multilingual coverage, 8192-token context vs 512). FAISS HNSW considered but rejected: approximate search trades recall for speed, which conflicts with `robust-and-reliable` NFR; exact search is fast enough at 1,814 chunks. `FlagEmbedding` library discarded: `XLMRobertaModel.__init__() got unexpected keyword argument dtype` across transformers 4.44–4.49; `sentence-transformers` wrapper resolves this cleanly. | `chunk_tokens`, `overlap`, `index.type` all in `configs/task.yaml`. `embed.model` and `embed.dim` (correct value: 1024) in config — code reads model name from config rather than hardcoding. Per-chunk cache in `store.build()` means incremental re-indexing works without full rebuild. | Offline, batch, CPU, once per corpus. Index persisted to `data/interim/index/index.faiss` + `chunks.jsonl`; both committed to git (small enough — ~1800 chunks). Chunk and embedding caches prevent redundant recomputation. | Chunk count, embedding dimension, and index size logged at every build. `store.load()` available for Stage 5 retriever. Dimension-mismatch guard raises a clear error if embedding model changes — forces intentional rebuild rather than silent corruption. |
