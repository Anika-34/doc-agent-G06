# Knowledge-base pipeline diagram (A2 — fill this)
Embed your diagram image here (or describe the stages): pages → clean → (enhance) → layout → OCR → chunk → embed → store.

1. **Raw → Pages (`loader.py`)**: Each source PDF in `data/raw/` is rendered page-by-page via `pdf2image.convert_from_path` at `render_dpi=150`, written as `data/interim/pages/<doc_id>/page-NNN.png`. Rendering is skip-if-exists per document, so a re-run doesn't re-render pages already on disk. Output is a flat list of `Page` records (`id = "<doc_id>:<page_stem>"`, `image_path`, `doc_id`), followed by a `validate()`/`snapshot()` call for corpus integrity bookkeeping.

2. **Pages → Filtered Pages (`preprocess.py`)**: Each page is grayscale-loaded, Otsu-binarized (inverted), cleaned with a 2×2 morphological open, then scored by connected-component blob count and ink-pixel ratio against `min_blob_area=15`, `min_blob_count=3`, `ink_ratio_threshold=0.002`. Pages under either threshold are physically moved (not copied) into `data/interim/blank/<doc_id>/`, and excluded from everything downstream — meaning a re-run sees a permanently shrunk `pages/` directory, by design.

3. **Filtered Pages → Enhanced Pages (`enhance.py`)**: A pass-through no-op. `run()` checks `cfg["enhance"]["enabled"]` (currently `false`) and returns pages unchanged if disabled; the `Enhancer` class and its `_upscale_2x` hook exist but are never invoked, per the sweep findings in Section 4 above.

4. **Pages → Regions (`layout.py`)**: For each page not already in the per-page region cache (`data/interim/layout/regions/<doc_id>/<page_stem>.json`), `DocLayout-YOLO-DocStructBench` runs at `imgsz=1184`, `score_thr=0.085`. Its 10 fine-grained output classes are collapsed to 4 (`heading`, `text`, `table`, `figure`) via a fixed name map. Raw detections then go through two cleanup passes: class-agnostic dedup (drop any box that overlaps another, of any class, by more than `dedup_iou_thr=0.5`, keeping the higher-confidence one — catching duplicate detections the model's own class-aware NMS misses), then containment filtering (drop any box more than 85% contained inside a larger kept box, since the larger box's OCR already covers that content). Final regions are cached as JSON plus a color-coded bbox-overlay debug PNG per page.

5. **Regions → OCR'd/Corrected Text (`ocr.py`)**: Figures are dropped (nothing to transcribe); remaining regions are sorted into page-spatial order. For pages not already cached (`data/interim/ocr/<doc_id>/<page_stem>.json`):
   - **Pass 1 — read**: Each region is cropped and read by Tesseract (`psm=7` for headings, `psm=6` otherwise, `oem=1`). If `dual_lang_word_level` is on, the region is first split into per-line boxes; any line whose "significant-character" Bangla ratio falls below `whole_bangla_ratio_thr=0.85` gets a word-level pass, where each Bangla-model word below `per_word_conf_thr=55` confidence is re-cropped and re-OCR'd with the English model, and the English reading is only accepted if its confidence beats the Bangla reading by `swap_margin=15` or more. Text is NFC-normalized and whitespace-collapsed.
   - **Pass 2 — correct**: Lines are pooled across the whole run; only lines whose significant-character Bangla ratio is ≥ `min_bangla_ratio_for_correction=0.6` are sent, in batches of 32, through the fine-tuned mT5 corrector (`ocr_fix:` prefix, beam=1, repetition penalty 1.3, no-repeat-3-gram, early stopping); a degenerate-output check (4+ repeated words in a row) reverts to the pre-correction line if generation collapsed.
   - **Pass 2.5 — cache**: Raw and corrected text are written per region, side by side, to the region cache.
   - **Pass 3 — score**: For pages with ground truth in `data/ground-truth-ocr/`, page-level raw text and corrected text are each diffed against GT via `jiwer` CER/WER, accumulated corpus-wide and (separately) for `held_out_docs = ["Krishi-Darpan"]`, and printed.
   - **Pass 4 — chunk seed**: One `Chunk` object is emitted per non-figure region (raw or corrected text, depending on `use_corrector`), tagged with a deterministic ID built from `page_id + bbox`.

6. **Regions → Chunks (`chunk.py`)**: Reading straight from the OCR region cache (not the Pass-4 `Chunk` objects, to keep raw/corrected text and region kind available), non-heading regions on a page are sorted spatially and greedily merged up to `target_tokens=256`, measured with the real `bge-m3` tokenizer. Table regions always break the current group and become their own standalone chunk. Any merged group that still exceeds `chunk_max_tokens=512` is split on Bangla dandi (`।`) sentence boundaries, carrying up to `overlap_tokens=32` of trailing sentences forward into the next piece so no sentence is orphaned at a boundary. Results are cached per page.

7. **Chunks → Vectors (`embed.py`)**: All chunk texts are batch-encoded by `BAAI/bge-m3` (`SentenceTransformer`, `batch_size=16`, `normalize_embeddings=True` — required since BGE models are trained for cosine similarity via normalized dot product).

8. **Vectors → Index (`index.py`)**: Vectors are added to a `faiss.IndexFlatIP` (exact inner-product search, matching the normalized embeddings). Chunk metadata is written to `chunks.jsonl` in the exact same row order the vectors were added, so a retrieved FAISS row index maps straight back to its `Chunk` record with no join needed.

> **Token-distribution check:** Across 3,403 regions, the token distribution is p50=67 tokens, mean≈100, p90=247, and p99=490. Only 0.6% of raw regions exceed the 512-token cap. This provides the empirical basis for `target_tokens=256` and `max_tokens=512` rather than using round-number guesses.
